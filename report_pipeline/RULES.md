# 분양공고문 검토보고서 — 절대 규칙

`scripts/verify.js`가 기계적으로 검사하는 항목 + 사람이 콘텐츠 작성 시 지켜야 할 규칙.

## 사실관계 (verify.js가 일부 자동 검사)
1. **원문 직접 추출만 사용.** `notebook_query`/`notebook_query_start`(LLM 요약) 결과를 그대로 보고서에 넣지 않는다. 반드시 `source_get_content`로 raw text를 받아 grep/정규식으로 직접 확인한 문장만 인용한다.
2. **소스 격리.** 노트북에 여러 단지가 섞여 있을 수 있으므로, 쿼리 전 `source_describe`로 대상 단지 소스인지 확인한다.
3. **고유명사·수치는 원문에 문자열이 실제로 존재하는지 카운트로 먼저 확인** 후에만 기재한다. 없으면 "수치 미기재"로 쓰고 그럴듯한 값(예: 등급, ★, 보증서번호)을 채워넣지 않는다.
4. **quoteBox(원문 인용)와 법인 자체 분석/외부 API 데이터를 명확히 구분**한다. quoteBox 안의 텍스트는 원문 그대로여야 한다.

## 문체·구성 (verify.js가 금지어 검사)
5. **버전/진행상황 라벨 금지.** "v1", "v2"... , "정정 안내", "이전 버전", "확정판" 등 세션 내부용 표현을 표지·본문에 쓰지 않는다. 매번 완성된 최종본처럼 작성한다.
6. **부록 페이지 없음.** 별도 "부록: 체크리스트" 페이지를 만들지 않는다. 우선순위·요청사항은 각 섹션의 코멘트박스 안에 바로 녹인다.
7. **지체상금·일반 재무부담(대출이자·수수료 등) 항목은 헤드라인에 넣지 않는다.** 입주민 관심도가 낮음 — 완전히 빼거나 4부(기타확인사항) 최하단에 1줄로만.
8. **뻔한 시공관행 수준의 독소조항은 넣지 않는다** (예: 서비스면적 오차, 엘리베이터 사양 차이 같은 통상적 disclaimer). 실제 개선협의로 실익이 있는 항목 위주로 선별.
9. **"개선요구/개선협의요청"에 초점.** "이 조항은 약관법 O조를 위반한다"는 단정적 법조문 인용보다, "이렇게 개선을 요구하면 좋겠다"는 실행 가능한 문구로 마무리.
10. **대출/LTV 규제분석 섹션은 기본 제외.** `content.includeLoanSection`이 명시적으로 true인 경우에만 렌더링.

## 시각자료
11. **위치를 지적하는 문장마다 단지배치도 크롭 이미지를 동반한다.** 전체 배치도 1장 + 언급되는 동/시설마다 개별 크롭+주석(PIL로 원/화살표/라벨 직접 그림).
12. **카카오맵 등 공공API 데이터는 표만이 아니라 시각화(막대그래프, 좌표기반 위치관계도 등)로도 제공**한다.
13. 모든 이미지는 `content/{slug}/assets/`에 두고, `content.js`에서 상대경로로 참조한다. verify.js가 파일 존재를 확인한다.

## 페이지 레이아웃
14. 모든 텍스트 블록에 `keepNext`/`keepLines`, 모든 표 행에 `cantSplit`을 기본 적용한다(`template/report_engine.js`에 이미 내장 — 새로 만들 필요 없음).
15. 폰트는 "맑은 고딕" 고정(존재하지 않는 폰트명 사용 시 파일 손상 위험 — 항상 이 폰트 사용).

## 검증 실패 시
`verify.js`가 실패하면 스크립트가 스스로 콘텐츠를 고치지 않는다 — 사람(에이전트)이 `content/{slug}/content.js`를 고치고 다시 `run_loop.js`를 실행한다.
